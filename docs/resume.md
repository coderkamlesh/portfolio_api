# Resume PDF — Frontend Guide

The resume is generated by the API on demand from the same tables the public site renders. There is no stored file and no template to maintain on the frontend.

- One request returns a complete, **ATS-friendly PDF** as the response body. It is not JSON.
- The PDF is rendered fresh on every request, so a content edit in the admin panel is reflected on the very next download.
- Every download is counted (see [analytics.md](analytics.md)).

## Endpoint map

| Method | Endpoint | Access token required | Success | Body |
|---|---|---:|---:|---|
| `GET` | `/api/public/resume/download` | No | `200` | `application/pdf` |

## The download button

The correct UI is a plain link, not a `fetch` + blob download:

```html
<a href="/api/public/resume/download" download>Download resume</a>
```

```jsx
<a href={apiUrl("/api/public/resume/download")} download="resume.pdf">
  Download resume
</a>
```

**Do not fetch this endpoint as JSON.** The response body is raw PDF bytes, so `response.json()` throws. Two correct options:

| Approach | When to use |
|---|---|
| Plain `<a href>` + `download` | Default. The browser handles the save dialog and shows progress. |
| `fetch` + `Blob` + object URL | Only when you need a programmatic action (for example, counting clicks yourself). You must revoke the object URL afterwards. |

If you use the same-origin API base, a relative href is enough. If the API lives on another origin, add `download` so the browser saves the file instead of navigating to it.

### Programmatic download

```js
const res = await fetch(`${API}/api/public/resume/download`);
if (!res.ok) throw new Error(`Resume download failed: ${res.status}`);

const blob = await res.blob();
const url = URL.createObjectURL(blob);
const a = document.createElement("a");
a.href = url;
a.download = "resume.pdf";
a.click();
URL.revokeObjectURL(url); // without this, the blob leaks until the tab closes
```

## Response headers

| Header | Value |
|---|---|
| `Content-Type` | `application/pdf` |
| `Content-Disposition` | `attachment; filename="resume.pdf"` |
| `Content-Length` | byte count |
| `Cache-Control` | `no-store` |

`no-store` is set for every public route. **The browser will not cache this**, so do not expect a second visit to be instant, and do not add a service worker cache for it without deciding on revalidation — a stale resume that a recruiter sees is worse than a slightly slower one.

## What the PDF contains

The layout is deliberately constrained. It is generated to survive automated parsing, not to look designed.

| Constraint | Why |
|---|---|
| Single column, no sidebar | Multi-column layouts interleave lines and scramble the reading order in ATS parsers. |
| Selectable text, no images | A scanned or outlined PDF is unreadable to a parser. |
| No icons, no dingbats | Symbol glyphs extract as garbage characters. |
| ASCII bullets (`-`) | The PDF core fonts are CP1252. A `•` (U+2022) would be written as mojibake. |
| Contact details in the body flow | Page headers and footers are frequently skipped by parsers, so the email and phone would be lost. |
| Sections in reading order | Summary → Skills → Experience → Projects → Education → Extras. |

### Character folding

Text is sanitized to ASCII before rendering. Curly quotes, en/em dashes, bullets, non-breaking spaces and accented Latin letters are folded to their ASCII equivalent (`don't`, `-`, `e`). A character with no ASCII equivalent becomes a visible `?`.

This means **the PDF can differ from the text you see on the website.** Write plain ASCII in the admin panel when you care about the PDF reading cleanly — for example prefer `Spring Boot` over `Spring Böt`, and a straight apostrophe over a typographic one.

### Date formatting

Dates render as `Mon YYYY`, and a current role shows `Present`:

```
Apr 2024 - Present
Jan 2022 - Mar 2024
```

Skills follow the category `display_order`. Empty tables contribute no section at all — a resume with no projects simply has no projects heading, rather than an empty one.

## Error responses

Errors use the standard envelope. The status is meaningful even though the body is not a PDF.

| Situation | Status | `code` | Message |
|---|---:|---|---|
| profile row has not been created yet | `404` | `profile_not_found` | `The profile has not been configured yet.` |
| PDF renderer failed | `500` | `resume_render_failed` | `Could not build the resume.` |
| database unreachable | `503` | `service_unavailable` | try again |

```json
{ "error": { "code": "profile_not_found", "message": "The profile has not been configured yet." } }
```

**A `404` here is an admin configuration gap, not a frontend bug.** The PDF cannot be built without a name, so the endpoint refuses rather than emitting a blank page. If a visitor sees this, the fix is to create the profile in the admin panel — the button itself is fine.

## What this endpoint does not do

- It does not return a JSON body or a temporary URL. There is nothing to poll.
- It does not require a token. Keep it public so the public site can use it directly.
- It does not cache. Every call re-renders and re-counts.
