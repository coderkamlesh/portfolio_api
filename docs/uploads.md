# Uploads (S3 presigned URLs) — Frontend Guide

Uploads let the admin panel attach images and a resume to the portfolio. The API never receives the file: it returns a short-lived presigned URL and the browser uploads straight to S3.

- The bucket is **private**. Public pages read objects through presigned GET URLs, not a public bucket URL.
- Object keys are generated by the API (`uploads/<kind>/<uuid><ext>`). The uploaded filename is **never** used as a key.
- If the deployment has no bucket configured, both endpoints answer `503 uploads_disabled` and the rest of the API keeps working.

## Endpoint map

| Method | Endpoint | Access token required | Success |
|---|---|---:|---:|
| `POST` | `/api/admin/uploads/presign` | Yes | `200` |
| `GET` | `/api/admin/uploads/download-url?key=...` | Yes | `200` |

## The three-step upload flow

```
1. POST /api/admin/uploads/presign   -> { upload_url, method, headers, key, expires_at }
2. PUT  <upload_url>                 -> direct to S3, with exactly the returned headers
3. save the returned `key` in the content that references the file
```

Step 3 matters: the API stores **keys**, not URLs. A project, a company or the resume record holds the `key`, and the public site asks this API for a download URL when it needs to render the file.

**Step 2 must not go through your API.** Sending the file to the API would waste Lambda memory and bandwidth and would hit the function timeout. `fetch(upload_url, { method, headers, body: file })` from the browser is the intended path.

### Step 1 — request an upload URL

```http
POST /api/admin/uploads/presign
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "kind": "project_image",
  "filename": "algo-master.png",
  "content_type": "image/png",
  "size_bytes": 284512
}
```

```json
{
  "upload_url": "https://portfoliov2-289210138514-ap-south-1-an.s3.ap-south-1.amazonaws.com/uploads/project_image/9f1c....png?X-Amz-Algorithm=...",
  "method": "PUT",
  "headers": { "Content-Type": "image/png" },
  "key": "uploads/project_image/9f1c2d3e-4a5b-4c6d-8e9f-0a1b2c3d4e5f.png",
  "expires_at": "2026-09-24T12:15:00Z"
}
```

### Step 2 — upload directly to S3

```js
const { upload_url, method, headers } = await presign(file);
await fetch(upload_url, { method, headers, body: file });
```

**Send the returned headers exactly as given.** `Content-Type` is signed into the request, so changing it — or letting the browser guess a different one — makes S3 reject the upload with `403`. When you pass a `File` to `fetch`, set the header explicitly rather than letting `fetch` derive it.

### Step 3 — store the key

```http
PUT /api/admin/projects/{id>

{ "image_url_key": "uploads/project_image/9f1c2d3e-....png" }
```

## Reading a private object

```http
GET /api/admin/uploads/download-url?key=uploads/project_image/9f1c2d3e-....png
```

```json
{
  "download_url": "https://portfoliov2-289210138514-ap-south-1-an.s3.ap-south-1.amazonaws.com/uploads/...?X-Amz-Signature=...",
  "method": "GET",
  "headers": {},
  "key": "uploads/project_image/9f1c2d3e-....png",
  "expires_at": "2026-10-24T12:00:00Z"
}
```

Use the `download_url` as an `<img src>` or an `<a href>`. **Refresh it before `expires_at`** — a cached URL keeps working, but a stale one returns `403`. The upload TTL is short (15 minutes by default) because the URL is used once; the download TTL is longer (60 minutes) because the public site reuses it across a page view.

## Field rules

| Field | Required | Rules |
|---|---:|---|
| `kind` | Yes | `avatar`, `project_image`, `company_logo`, `resume` — case-insensitive input |
| `content_type` | Yes | must be accepted for the chosen kind |
| `size_bytes` | No (but send it) | `> 0` and within the kind's ceiling |
| `filename` | No | only checked for a matching extension; never used to build the key |

### Accepted types and ceilings

| Kind | Content types | Max size (default) |
|---|---|---:|
| `avatar` | `image/jpeg`, `image/png`, `image/webp` | 5 MiB |
| `project_image` | `image/jpeg`, `image/png`, `image/webp` | 5 MiB |
| `company_logo` | `image/jpeg`, `image/png`, `image/webp` | 5 MiB |
| `resume` | `application/pdf` | 10 MiB |

**SVG is not accepted for any kind.** An SVG file can contain script, so serving one from the bucket would be a stored-XSS vector against the public site. Convert logos to PNG.

**`size_bytes` is checked against the declared value, not the real one.** The API cannot inspect bytes it never receives. A caller can still upload a larger object by lying about the size; if that matters, keep S3 lifecycle rules or a bucket policy alert as a backstop.

### Error responses

| Situation | Status | `code` | Message |
|---|---:|---|---|
| no bucket configured | `503` | `uploads_disabled` | `File uploads are not configured on this deployment.` |
| unknown `kind` | `400` | `validation_failed` | lists the accepted kinds |
| `content_type` not allowed for the kind | `400` | `validation_failed` | lists the accepted types and names the kind |
| `size_bytes` zero or negative | `400` | `validation_failed` | `size_bytes must be greater than zero.` |
| `size_bytes` over the ceiling | `400` | `validation_failed` | names the ceiling and the kind |
| `filename` extension ≠ `content_type` | `400` | `validation_failed` | names both |
| `key` outside the upload prefix, or unclean | `400` | `validation_failed` | `key must be a clean object key.` |
| S3 could not sign the request | `502` | `upload_unavailable` | try again |

`key` is checked strictly: a key containing `..`, a doubled slash, or any whitespace is **rejected, not cleaned up**. That way the key the API authorises is always exactly the key you asked for.

## Bucket setup you must complete

The code is ready, but these are AWS-side steps that no Go code can do:

1. **IAM** — the Lambda execution role needs `s3:PutObject` and `s3:GetObject` on `arn:aws:s3:::portfoliov2-289210138514-ap-south-1-an/uploads/*`. Grant it on the prefix, not the bucket root: a presigned URL's capabilities are exactly its signing role's.
2. **CORS** — the browser makes a cross-origin `PUT`. Without a CORS rule the preflight fails and uploads break even though the code is correct:

   ```json
   [
     {
       "AllowedOrigins": ["https://<your-frontend-domain>", "http://localhost:5173"],
       "AllowedMethods": ["GET", "PUT"],
       "AllowedHeaders": ["content-type"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3000
     }
   ]
   ```

3. **Block Public Access** — keep it **on**. Private bucket plus presigned GET is the intended design.

## Configuration

| Variable | Default | Notes |
|---|---|---|
| `S3_BUCKET` | *(empty — uploads disabled)* | `portfoliov2-289210138514-ap-south-1-an` |
| `S3_UPLOAD_PREFIX` | `uploads` | all keys start with this |
| `S3_PUT_PRESIGN_TTL_MINUTES` | `15` | upload URL lifetime |
| `S3_GET_PRESIGN_TTL_MINUTES` | `60` | download URL lifetime |
| `S3_MAX_IMAGE_BYTES` | `5242880` | ceiling for image kinds |
| `S3_MAX_RESUME_BYTES` | `10485760` | ceiling for the resume |
| `AWS_REGION` | `ap-south-1` | already used by SES |
